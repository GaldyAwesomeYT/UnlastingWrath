# Parry Arena (Roblox)

A Roblox PvP/PvE game built around a blade. Players swing it with the mouse, guard with F, and clash blades to parry.

## Stack and workflow
- Rojo is no longer used. Scripts are edited directly in Roblox Studio through the Roblox_Studio MCP server (Edit mode only; the Edit datamodel is blocked during Play). Studio is the source of truth.
- `src/` is a mirror: after every change made in Studio, copy the same change into the matching file in `src/` and commit it. (`default.project.json` and `rokit.toml` are left over from Rojo and unused.)
- After every change, save the place with the MCP `save_place` tool (same as File > Save to Roblox). Saving never publishes.
- Test with Studio's Play button. There is no automated test suite yet.

## Layout
- `default.project.json`: maps `src/server` → ServerScriptService/Server, `src/client` → StarterPlayerScripts/Client, `src/shared` → ReplicatedStorage/Shared, `src/replicatedfirst` → ReplicatedFirst (loading screen; restart `rojo serve` after changing this file).
- `src/shared/Config.luau`: all tuning numbers. Change values here, not in logic.
- `src/shared/Remotes.luau`: RemoteEvents (Feedback, Round, Scores, Dash, Ready, ReadyState, MatchStart, Block, Options, Sheathe, ScoresRequest, QuickDraw, Keybinds, Leaderboard, PracticeExit). Server creates them.
- `src/server/BladeService.luau`: creates each player's blade and handle, and hands the blade's physics to that player's client.
- `src/server/CombatService.luau`: server-authoritative blade hits (by body part), clashes (parries), guard, sheathe state, stuns, kill credit, the Max-Clash bar, and the dummy sword AI.
- `src/server/TrainingService.luau`: training mode (you vs your own dummy).
- `src/server/GameService.luau`: ready-up queue (needs `Config.MatchSize` players), lobby countdown, first to KillsToWin between the fighters, intermission, kill counts, post-kill reset countdown, and scores broadcast.
- `src/server/RoundState.luau`: shared "active", "paused", and "fighters" state.
- `src/server/Main.server.luau`: builds the floor and training dummy, starts services.
- `src/client/Main.client.luau`: input, HUD (mode label, feedback, self health bar top-left, opponent health bars top-right, stun bar, dash cooldown bar, round status, parry flash, scoreboard, Ready button), body facing, dash, duel intro camera.
- `src/client/Weapon.luau`: blade control and arm posing. A virtual cursor in an on-screen circle aims the blade, the arms are posed through the shoulder Motor6Ds (joint kept on the shoulder), plus guard, sheathe, and look-around.
- `src/client/LockedCamera.luau`: shift-lock style camera fixed to the head, turning with the body's facing (plus look-around offsets). Sheathing or drawing the blade pans smoothly between it and Roblox's normal camera (`Config.CameraPanTime`).
- `src/client/LockOn.luau`: lock-on target choice (the other fighter in a match, else the nearest training dummy) and the marker over it. `Main.client.luau` turns the body toward it.
- `src/client/HealthBars.luau`: name and health bars over other players' and dummies' heads, hidden while the local player is a fighter in a duel (`HealthBars.setInMatch`). Culling: only the closest `Config.HealthBarMaxVisible` (10) on-screen characters within `Config.HealthBarMaxDistance` get a bar; refreshed every `Config.HealthBarRefreshTime`.
- `src/client/Leaderboard.luau`: the fullscreen leaderboard opened by the Scoreboard key (Tab by default; Esc or the key closes it). Tabs: Server (this match's kills, pushed through `Scores`), Global (all-time kills) and Regional (all-time kills among players from the same country or region). While open the mouse is free and gameplay input is ignored (`Main.client.luau` passes `leaderboard.isOpen` to `Weapon.start`).
- `src/server/LeaderboardService.luau`: all-time kills in OrderedDataStores ("GlobalKills" and "RegionKills_<code>", the code from `LocalizationService:GetCountryRegionForPlayerAsync`). `GameService` calls `recordKill` when a kill is credited (duel kills only, not dummies). Boards are cached for 60s and requests are rate-limited. Needs the same DataStore access as the keybinds, and prints warnings when a read or write fails.
- `src/client/Menu.luau`: title menu (Play, Settings help, Controls page). The old Mode and Difficulty buttons are gone; Play always means Duel. The server's Training mode code (`TrainingService`, `Config.GameModes/Difficulties`) is still there but nothing in the UI reaches it.
- `src/server/PracticeService.luau`: practice mode. Adds a ProximityPrompt (E, no physical button) in front of each `Stand<N>_Bamboo_Node` in Workspace.JapaneseLobby, on an Attachment inside the log, built at runtime. Pressing it sets the player attribute `Practicing`, moves the player in front of the log, and one player per stand. A moving blade (`CombatService.getBlade`, `Config.HitMinSpeed`) touching the player's own log cuts it: the log sways, chips fly, the player gets the "Cut" feedback. Ends on the `PracticeExit` remote, a respawn, or leaving. `GameService` ignores practicing players in the Ready queue.
- `src/client/Practice.luau`: the client half. While `Practicing` is set, every other player (body, accessories, face, blade, default name tag) is hidden locally and the EXIT PRACTICE button shows (hold the FreeCursor key to click it). Main.client turns lock-on off and hides the Ready button; `HealthBars.setPractice` hides head bars.
- `src/client/Controls.luau`: the player's own key bindings per move. All input code asks here (`Controls.matches`, `Controls.isDown`, `Controls.label`) instead of reading keys from Config. The Controls page in the menu rebinds them (click a move, press a key or mouse button; Esc cancels; a key another move uses is swapped; W, A, S, D, Space can't be bound).
- `src/shared/ControlActions.luau`: the rebindable moves (Guard, Sheathe, LockOn, Dash, Look, QuickDraw, FreeCursor, Scoreboard), their defaults (from the `Config.*Key` / `*Button` values), and binding validation.
- `src/server/KeybindService.luau`: saves each player's bindings in a DataStore ("Keybinds") over the `Keybinds` remote, validating everything the client sends. Without DataStore access (Studio's API Services off) bindings last for the session only.

## Rules
- Combat logic stays on the server. The client moves its own blade and sends intent (guard, sheathe, dash) and displays results. The server reads the replicated blade for hits and clashes.
- Player-vs-player combat is only allowed between the two fighters while `RoundState.active` is true. The training dummy always works.
- At round start the server freezes the fighters and pauses combat for the duel intro's total time (the `Config.Duel*` values). The camera is client-only and uses Roblox's built-in camera APIs.
- Matches are 1v1 from a ready-up queue: a match starts only after `Config.MatchSize` players press Ready and stay ready through `Config.LobbyCountdown`. Everyone must press Ready again for the next match. Fighters spawn at x = ±12 on the arena's center line, facing each other (`startMatch` in `GameService`; assumes `MatchSize` = 2).
- Controls (these are the defaults; players rebind them on the Controls page, so never hard-code a key in input code, use `Controls`): the mouse moves the blade (no click to attack), F holds the guard, hold right mouse and move the mouse to look around (the blade holds still), X sheathes or draws the blade, Shift dashes, Q toggles lock-on (on by default: the body always faces the opponent, so A/D strafe without turning the camera; with no target or lock-on off, the body never turns toward its movement: A, D, S and W all walk without turning, and releasing right mouse turns the body to face where you were looking), hold Left Alt to free the cursor for GUI buttons (gameplay input is locked meanwhile), Tab opens the fullscreen leaderboard. The old Simple/Manual click modes (M) and Q block are gone.
- Blade hits: the server samples points along the blade and tests them against the target's real part boxes (`Config.BladeThickness`). The blade must be moving (`Config.HitMinSpeed`), so a blade resting against someone deals nothing. Damage scales with the part touched (`Config.HitMultipliers`: head, torso, limb). Don't go back to a distance-from-center check.
- Dummy swords: each dummy holds a physical sword (parts "Blade" and "Grip" in its model) that the server moves every heartbeat (`updateDummy`): rest, windup (the target gets "Telegraph"), a flat swing (the only time it can hurt), recover. It swings when a player is within `Config.DummyAggroRange` (6 studs), so the player must walk up to it. The normal hit and clash checks apply to it, and it only hurts players. A player's blade clashing with a dummy's sword is a parry: the dummy is stunned for `Config.ParryStunDuration` (head turns blue) and its swing is cancelled; one moving blade is enough against a dummy. A killed dummy revives after `Config.DummyReviveTime` (its Humanoid has the Dead state disabled, or Health writes would be ignored).
- Max-Clash bar (player vs player): a clash stuns nobody and the players keep moving their blades. Each clash adds `Config.ClashBarGain` to both players' bars. Full bar = weakened for `Config.WeakenedDuration`: walk speed x`WeakenedSpeedMultiplier`, blade Align responsiveness x`WeakenedBladeResponsiveness` (the server sets it on the constraints), damage x`WeakenedDamageMultiplier`; the bar then empties and resets. The bar starts draining `Config.ClashBarIdleTime` (3s) after the last clash. The server publishes it as the character attributes `ClashBar` (0-1; counts the weakened time down while weakened) and `Weakened`; the HUD bar above the dash bar reads them. `CombatService.clearClash` resets it after each kill. Written; tested in Studio only with a stand-in opponent (the real two-player clash is untested).
- Sheathed mode (X): the blade sits on the left hip and can't hit, clash or guard (server flag set through the `Sheathe` remote). Once fully sheathed the game is in "default mode": Roblox's normal camera, free cursor, no cursor circle, no look-around, the body turns toward movement, and the arms are animated too. While the blade is drawn, the Animate script keeps running for the legs (`Config.LegAnimation`); While drawn, each arm hangs on its own Weld (the shoulder Motor6D is disabled), because the animator only drives Motor6Ds and so can't move the arms; default mode switches the Motor6Ds back on (`weldFor` and `releaseArms` in `Weapon.luau`). Clearing the Motor6D Transform after each animation update did not work. With `LegAnimation` false, the script is off while drawn. Fully sheathed, the blade is pinned to the hip each frame with its Align constraints switched off (`pinBladeToHip`), because the constraints trail behind a walking character. Keep both modes working.
- Draw / sheathe animation (`sayaFrameAt` / `bladeFrameAt` in `Weapon.luau`, tuned by `Config.SheatheTime` and `Config.Draw*`): both hands lift the whole sheathed sword from the hip to above the head, level with the hilt toward the right (`DrawOverheadPoint` / `DrawOverheadDirection`); the right hand pulls the katana out sideways (`DrawPullDistance`) while the left holds the saya; the right brings the katana down to the ready pose while the left lowers the saya back to the hip. Sheathing runs it backwards. The saya is its own client-owned part (`Saya.SayaBody` with Align constraints, made in `BladeService`; pinned to the hip like the blade when it is there, `placeSaya`). The blade pieces fade in and out on the server (`BladeService.setBladeHidden`, `FADE_DRAW` / `FADE_SHEATHE`, matching the phases) so the blade never shows through the saya. Arms may stretch to `DrawArmStretch` during it. Checked in Studio (mid-draw screenshot and pose sampling).
- Quick draw: while sheathed, hold left click (`Config.QuickDrawButton`) and swing the mouse right, up or down (`Config.QuickDrawThreshold` pixels) to draw and slash straight out of the sheath. The client scripts the slash arc (`Config.QuickDrawTime`) through the normal blade, so hits and clashes use the usual checks; the `QuickDraw` remote tells the server, which confirms the player was sheathed and gives hits within `Config.QuickDrawBonusTime` a `Config.QuickDrawBonus` damage multiplier. A swing to the left does nothing.
- Edge turning: pushing the cursor past the edge of the aim circle turns the player. Sideways overflow turns the body (and the camera with it) through `pendingTurn` (`Config.EdgeTurnSensitivity`); vertical overflow tilts the camera up to `Config.EdgePitchLimit` and it eases back to level. While locked on (`Weapon.setLockedOn`, set each frame by `Main.client.luau`) the push turns and tilts nothing, so turn freely by toggling lock-on off. The circle's edge is not drawn (`Config.ShowAimCircle` false); only the cursor dot shows.
- Camera and body facing: the locked camera follows the body's facing, so the body must not auto-turn toward its movement (A/D pivot, S spins). Outside default mode `Main.client.luau` keeps `AutoRotate` off. The body's orientation follows the player's look: `Weapon.takeLookTurn` returns the yaw of a finished right-mouse look-around, and `Main.client.luau` turns the body by it, so the view doesn't jump when the camera goes back to following the body.
- After every kill, combat pauses for `Config.KillResetCountdown` seconds, then the fighters are moved back to their match spots (x = ±12, facing each other, not the spawn location) and healed to full. Written, not yet tested in Studio. Kill counts live on the server; clients get them via the `Scores` remote.
- Don't add sound IDs or assets you can't confirm are usable. `Config.ParrySoundId` stays empty until the user sets it.
- Make small, focused changes and tell the user which files changed so they can copy them to `C:\Projects\RobloxGame` (or commit them locally).

- Round duel intro (fighters only): the server anchors both fighters and pauses combat for the sum of `Config.DuelWideTime`, `DuelCloseTime` (×2), `DuelReturnTime`, and `DuelPanTime` (5.0s), and fires `MatchStart`. The client moves only the camera: wide level side-on shot, diagonal close-up on each fighter's midsection from the camera side (weapon-ready framing), wide shot again, then pan to the normal follow view. If the local character dies during the intro, the follow camera is restored immediately. Written, not yet tested in Studio.
